# 电动力学 AI 助教

基于属性知识图谱的《电动力学》课程答疑系统。三大能力：

1. **概念答疑**：学生提问 → 图谱定位知识点 → 沿先修链回溯 → GLM 生成回答 → **每句话标注依据来源**
2. **拍照解题**（答疑输入框左侧的 **＋** 按钮）：拍**一道**题目 → GLM 视觉识别（公式转 LaTeX）→ 图谱标记用到的知识点 → 沿先修链找根因 → **一次只推进一步地引导，不给答案**
3. **推导溯源**：对指定知识点回答「这个式子是怎么来的」，沿数学推导链回溯到麦克斯韦方程组

与「智卷」（初中物理错题分析）是**独立项目**：智卷解决"学生哪里不行"，本项目解决"这个概念为什么想不通"。

> **架构总览与界面图**：打开 [`docs/diagrams/index.html`](docs/diagrams/index.html) 可直接浏览 8 张结构图（含系统总览、属性图模型、解题链路、根因回溯、界面落点）。

## 核心设计

### 1. 凡是能算出来的，绝不交给模型猜

先修链、共同根因、节点邻域全部由 **Kuzu 图运算**确定性求出，再作为"已算好的事实"交给模型转述。
模型只负责把结论讲成人话——它可以组织语言，但不能替学生判断哪里不行。

这是可信度的地基。如果让模型自己"感觉"学生缺什么，整个溯源体系就失去意义。

### 2. 一张属性图，三族关系

图谱用**属性图（Labeled Property Graph）**建模：节点分四类标签，**边是一等对象**，有自己的类型名和属性。
三类关系族共用同一套知识点节点，但各自回答不同的问题、走不同的校验：

| 关系族 | 回答什么 | 形态 | 约束 |
|---|---|---|---|
| **Graph A** 结构 | 由什么构成 | 树：章 → 节 → 知识点 | 必然无环 |
| **Graph B** 教学先修 | 该先补什么 | DAG：先修边 + 关联边 | **必须无环**（Kahn 检测） |
| **Graph C** 数学推导 | 这个式子怎么来的 | 有向图：推导 + 前提 | **允许成环**（E ⇄ B 是物理事实） |

为什么必须分族：先修关系绕成环就是循环论证，推导关系却天然有环。
硬塞进一张无环图，Kahn 校验会把物理上正确的关系判成错误。

**Graph B 是本项目最核心的资产**——任何公开资源里都不存在，必须依据物理逻辑自建（见 `data/graph-b-prerequisites.json`）。

> 实现现状：`npm run ingest` 目前只把 Graph A / B 灌入 Kuzu（`src/kuzu.mjs` 的 `SCHEMA` 有 5 张 REL TABLE）；
> Graph C 仍以 JSON 为事实源，由 `src/mathgraph.mjs` 直读。两者同属一张属性图模型，只是落地节奏不同。

### 3. 引用协议是硬约束

模型必须使用：

- `[[KG:节点ID\|名称]]` —— 依据来自图谱知识点
- `[[TXT:节点ID\|教材出处]]` —— 依据来自教材章节
- **不加标记** —— 系统判定为「AI 推断」

后端做节点存在性校验。**编造的节点 ID 会被拦下并降级为无效引用**，绝不放行。

宁可少标，不可乱标。

### 4. 关系有名字，对齐 W3C SKOS

图上的每条边都是**具名关系**，不是"放在哪个数组里"就算数。

- `data/edge-types.json` —— 关系词表。**SKOS 原生关系 13 种**（标签类 3 / 语义类 5 / 映射类 5），
  外加本项目的领域扩展（结构族 / 主题族 / 教学族 / 推导族）。
  每种关系带三个数学性质：`symmetric` / `transitive` / `allowsCycle`。
- 分类在**读取时**算（`src/relations.mjs`），不写回数据文件 ——
  12 条关联边的迁移（`概念推广` → `skos:broader`、`量级递进` → `seriesOrder` …）属内容决策，
  等教研确认后再落库。届时只需删掉读取时的映射兜底，接口与界面都不用动。
- **点画布上的任意一条边**即可看到：关系中文名、标准来源徽标（`skos:broader` / 领域扩展）、
  读法、两端节点（可点跳转）、边的依据原文。图例里有「关系词表」，列出 SKOS 全部 13 种及落地状态。

> ⚠️ 先修与推导**不是** SKOS 关系。SKOS 只规范概念的名称与概念间关系，不涉及认知顺序与数学推导，
> 所以它们标为「领域扩展」，不冒充标准。
>
> ⚠️ 对称关系不画箭头。是不是对称由词表决定（`对称类比`、`并列定理` 对称；
> 先修、上下位、跨表映射不对称），画箭头前先看 `symmetric`，不要按边表位置猜。

## 拍照解题（并入答疑窗口）

**不做独立标签页**：拍照入口是答疑输入框左侧的 **＋** 按钮，识别结果与后续引导
都落在同一个对话流里。学生不必在"问问题"和"传作业"之间切换，追问也在同一段上下文里继续。

### 流程（单题模式）

```
点 ＋ 选/拍一张照片
      │
      ├─ 上传前图像质量预检（分辨率/亮度/对比度/反光，几百毫秒）
      │
      ▼
题目照片 ──GLM 视觉──▶ 题干 + LaTeX ──▶ 图谱标记 ──▶ 诊断 ──▶ 根因回溯 ──▶ 引导反馈
          （glm-4v-plus）                          （图运算）    （一次只推进一步，不给答案）
```

进度条与阶段列表直接长在这条助教消息里；做完之后输入框变成"就这道题接着问"，
点结果里的「结束本题」即回到普通答疑。

> **一次只处理一道题**。识别阶段若发现图中有多道题，会明确提示"请一题一图"，
> 但不会硬拒绝请求（模型对"图里有几道题"的判断本身也可能出错，
> 拿它当拒绝理由会让用户陷入传不上去的死局）。

### 识别为什么用 GLM 视觉直读

作业链路的识别由 **GLM 视觉模型**（`src/vision.mjs`）完成，一次请求直接返回结构化的
题干 + LaTeX 公式。同一张翻拍图的实测对比：

| | 耗时 | 识别结果 |
|---|---|---|
| **glm-4v-plus**（采用） | **5.4s** | `electromagnetic`、`\omega`、`\nabla\times E` 全部正确 ✅ |
| glm-4.5v | 10.0s | 把图中的错字原样抄下来，说明没真正"看懂" |
| glm-4v-flash | 12.2s | 一般，且会自己补推导（越界） |

`GLM_VISION_MODEL` 可在 `.env` 里切换，与对话模型共用同一个 Key。

### 三条设计边界

这个功能的价值不在于"能批改作业"，而在于**知道自己什么时候不该开口**。

#### 边界一：模型只负责"看"，不负责"检验题面"

识别环节的唯一职责是**如实转写**：看到什么写什么。

- 不判断题目本身是否合理、是否缺条件
- 不修正明显的错别字（照原样转写）
- 不替学生补全残缺的公式

一旦识别环节开始"自作聪明"，下游的诊断就失去了基准——
你无法再区分"这是书上印错了"还是"这是模型改过了"。

（注意：这与「诊断」环节不矛盾。诊断是明确标注的另一件事，
且只对确定的内容做判断，见边界二。）

#### 边界二：识别不确定的地方，绝不用来批评学生

视觉模型仍会看错下标、漏字、把反光当成文字。
所以识别结果里保留了 `uncertain`（模型自报不确定处），并且：

- `uncertain` 里列出的地方**不允许**作为判错的依据，只能写进 `notCovered`
- 若不确定处恰好位于解题的关键步骤上，整体判 `unreadable` 并说明原因
- 题干根本没识别出来时，直接给"无法判定" + 针对性的重拍建议

**宁可说"这里没认出来，请重拍"，也不猜着批改。**
把识别误差当成学生的错误去批评，伤害比漏判大得多。

#### 边界三：只引导，不给答案

| 允许 | 禁止 |
|---|---|
| 指出第一个值得怀疑的地方，问他为什么这么写 | 写出完整推导步骤 |
| 反问一个更基础的问题，把他拉回物理图像 | 给出最终结果或关键中间结果 |
| 说出该用哪个方程的**名字**（不写它的内容） | 写出一整段可以直接抄进作业的解答 |
| 让他自己核验量纲、极限、特例 | 泄露结论性物理关系（如"E×B 指向传播方向"） |
| 把提示拆成更小的问题再问回去 | 替他重写式子（让他分不清该看哪个） |

边界规则写在 `src/homework.mjs` 的 `GUIDE_RULES`。
系统还会对生成的回复做**泄露信号检测**（`detectAnswerLeak`），发现可疑之处会回传前端告警并在日志留痕。

这里刻意不做关键词黑名单式的硬拦截——物理表述太灵活，误杀率会很高，
一旦拦错学生会收到一段面目全非的回复。只做信号提示，让边界可见、可观察。

### 上传前的图像质量预检

翻拍质量是识别成败的第一因素，但整条链路要跑 60~90 秒才知道照片不合格。
前端在上传前用 canvas 缩到 400px 后统计灰度直方图，查五件事：

| 检查项 | 触发阈值 | 判定 |
|---|---|---|
| 分辨率 | 长边 < 900px / < 1400px | bad / warn |
| 亮度 | 均值 < 60 / < 95 | bad / warn |
| 对比度 | 标准差 < 28 / < 38 | bad / warn |
| 反光过曝 | 纯白像素 > 8% | warn |
| 阴影遮挡 | 近黑像素 > 10% | warn |

判为 `bad` 时会先弹确认框，省掉一次空跑。
只看全图统计特征，不做版面分析——那些需要真正的 CV，成本高且容易误判。
跨域图读不到像素时直接放行，不阻断上传。

### 进度条

进度条挂在**这条助教消息内部**（不再有独立的作业面板），绑定 SSE 的 `stage` 事件按阶段推进：

```
识别题目 34% → 图谱定位 52% → 核查解答 72% → 回溯先修链 86% → 生成反馈 96% → 完成 100%
```

按**阶段数**推进、不按耗时加权：各阶段实际耗时波动大（模型推理长短不一），
按时间估算会长时间卡在某个数字不动，观感更差。完成后进度条自动收起，只留结果。

### 心跳：长耗时阶段不能"看着像卡死"

实测单次链路 **60~90 秒**，其中 **核查解答 20~48 秒、生成反馈 27~32 秒完全静默**
——这两步各是一次完整的模型调用，中间不产生任何事件。进度条会干停在 72% / 96%，
和真的卡死没有区别（用户就是这样报"卡住了"）。

所以服务端每 **4 秒**推一次 `tick` 事件：

```json
{ "type": "tick", "stage": "diagnose", "elapsedSec": 37 }
```

前端据此把"已耗时"持续写到阶段行与进度条上（`核查解答 · 已 37s`），
并保持进度条的流动动画。另有三道兜底：

| 机制 | 作用 |
|---|---|
| 服务端 `tick`（4s） | 让长等待始终可见 |
| 前端看门狗（20s 无事件） | 链路真断了就明确报错，不让用户干等 |
| LLM 超时收紧到 60~90s | 原来 120~180s，真卡住会静默近 3 分钟 |

契约测试里加了「全程有心跳事件」「相邻事件最大间隔 < 10 秒」两条断言，防止以后把心跳删掉。

### 布局：窄窗口会逐级退让

`main` 是三栏 grid。**三栏都写固定宽度会在窄窗口下横向溢出，把右侧对话区推出可视范围
——表现就是"切到某个 tab 一片空白"**（曾真实踩到）。现在：

| 视口宽度 | 布局 |
|---|---|
| > 1180px | 244px / 弹性 / 400px 三栏 |
| ≤ 1180px | 196px / 弹性 / 360px |
| ≤ 900px | 隐藏课程结构栏，弹性 + 380px |
| ≤ 700px | 只留对话区（全宽）；图谱画布与图例隐藏 |

### 实测效果

用一份三题印刷体（第 2 题故意把位移电流说成"实际流动的电流"）测试单题模式：

- 视觉识别准确读出「写出真空中麦克斯韦方程组的积分形式与微分形式」
- **正确检测出图中还有 4.2、4.5 两题**，提示"请一题一图"
- 判定「仅有题目」（照片里确实只有题干），未凭空替他解答
- 根因回溯出「通量与环量」「标量场与矢量场」「旋度」三个硬前提
- 开场引导未泄露答案，并自然地把"下次一题一图"带进反馈

### 耗时

单题实测 **60~90 秒**，且**波动很大**：

| 阶段 | 实测区间 | 产生事件 |
|---|---|---|
| 识别题目（视觉） | 3.6~7.8s | 有 |
| 图谱定位知识点 | 4~6s | 有 |
| **核查解答** | **22~48s** | **静默，靠心跳** |
| 回溯先修链 | 0.1s 级（纯图运算） | 有 |
| **生成反馈** | **27~32s** | **静默，靠心跳** |

两个大块都是完整的模型调用，占全程 80% 以上——这也是必须做心跳的原因（见上文）。
图运算（定位/回溯）几乎不耗时，耗时全在模型上。

## 快速开始

**环境要求**：Node.js ≥ 18（本项目在 22.x 上开发验证）。无需 Docker，无需 Python。

```bash
git clone <本仓库地址> && cd em-tutor
npm install

# 1) 配置密钥（必需，否则答疑与拍照功能不可用）
cp .env.example .env
#   然后编辑 .env，填入自己的 GLM_API_KEY
#   Windows: copy .env.example .env

# 2) 启动（首次会自动建库）
npm start
```

打开 http://localhost:3200

> 没有密钥也能启动服务、浏览图谱与界面，只是调用模型的功能会报「缺少环境变量」。
> 密钥申请见 [配置](#配置) 一节。

### 分开执行

```bash
npm run ingest     # 源数据 → Kuzu 建库（幂等，可反复跑）
npm run check      # 校验图谱数据：引用完整性 + DAG 无环 + 冗余边
npm run server     # 只启动服务
npm run stop       # 优雅停止（先释放 Kuzu 句柄再退出）
```

> **停止服务请用 `npm run stop`，不要强杀进程。**
> Kuzu 用文件锁独占数据库，强杀会跳过 `closeDb()`，紧接着重启可能撞上
> `Could not set lock on file`。服务端对此有退避重试（6 次），但优雅停止更省事。

### 自检

```bash
npm run llm:check      # GLM 连通性（非流式 + 流式）
npm run mineru:check   # MinerU 鉴权
npm run web:check      # 答疑接口契约（逐字段校验，53 项）
npm run hw:check       # 作业接口契约（SSE 事件 + 心跳 + 三条边界，50 项）
npm run hw:ui          # 前端渲染逻辑（真实数据驱动，49 项）
npm run derive:ui      # 推导链渲染（Graph C，32 项）
npm run edge:ui        # 边的命中/箭头/关系卡片/词表面板（60 项）
npm run math:check     # 全部 LaTeX 公式渲染检查（138 条）
npm run hw:timing      # 链路计时：每阶段耗时 + 静默间隔
npm run debug:ui       # 页面空白诊断（连真实服务点全部 tab；需 npm i --no-save jsdom）
npm run check          # 图谱自身校验六项（引用完整性/无环/自环/重复边/冗余边/覆盖率）
npm run check:c        # Graph C 校验（可追溯性；不做无环检测）
npm run diagrams       # 把 docs/diagrams/*.svg 批量导出 2 倍 PNG（只用本机浏览器）

npm run ask "为什么需要位移电流？"    # 命令行问答，输出逐句溯源
npm run hw                          # 作业全链路（照片 → 引导），分阶段打印
npm run hw -- samples/homework-typed.png   # 指定图片

npm run query -- stats                # 图谱统计
npm run query -- trace 平面电磁波 3   # 先修链回溯
npm run query -- roots "电偶极辐射,磁偶极辐射,天线辐射" 3   # 根因诊断
```

> `hw` / `hw:check` 会直接读写图谱库文件，跑之前先 `npm run stop` —— Kuzu 是单写者。

`scripts/` 下的样例图（`samples/`）可用于回归：

| 文件 | 拍摄情况 | 预期 |
|---|---|---|
| `homework-multi.png` | 干净白底，三题印刷体，其中一题埋了概念错误 | 只处理一道，提示"还有 4.2、4.5" |
| `homework-typed.png` | 有纸面质感/透视的翻拍 | 识别仍有少量不确定处 |
| `textbook-page.png` | 手机拍课本内页 | 公式有看不清处，给重拍建议 |

## 配置

密钥写在项目根目录的 `.env`（已被 `.gitignore` 排除）。模板见 [`.env.example`](.env.example)：

```ini
# 对话模型（诊断、引导）
GLM_API_KEY=<你的智谱 API Key>
GLM_BASE_URL=https://open.bigmodel.cn/api/paas/v4
GLM_MODEL=glm-5.3-flash

# 视觉模型（题目照片识别）—— 与上面共用同一个 Key，无需单独申请
GLM_VISION_MODEL=glm-4v-plus

PORT=3200
```

密钥在 https://open.bigmodel.cn 申请。**本项目只使用 GLM 系列模型。**

## 公式渲染

所有 LaTeX 公式由 **KaTeX 本地渲染**（`web/vendor/katex/`，1.5MB 含字体，离线可用）。

`renderRich()` 的顺序很关键，别改：**先从原始文本抽出数学段 → 转义其余内容 → 还原数学**。

若反过来先转义，LaTeX 里的 `&` 会变成 `&amp;`（矩阵/对齐环境的对齐符），`<` `>` 也会被破坏，
KaTeX 就认不出这些公式了。代码块内的内容会被单独保护，不参与数学渲染。

用 `npm run math:check` 可以全量验证 138 条公式能否渲染。

## 环境约束（踩过的坑，别绕回去）

### 1. Kuzu 库文件必须放在纯 ASCII 路径下

Kuzu 原生层用窄字符 API 处理文件路径。项目目录含中文（`桌面/AI错题智能体`），
直接报：

```
No mapping for the Unicode character exists in the target multi-byte code page.
```

因此图谱**源数据**放在项目内（可版本管理），而 Kuzu **库文件**放在
`%LOCALAPPDATA%\em-tutor\`（纯 ASCII，可随时用 `npm run ingest` 重建）。
可用环境变量 `EM_KUZU_DIR` 覆盖。

只有**路径**受限，节点属性里的中文完全正常。

### 2. Kuzu API 全异步，且第二个位置参数不是查询参数

```js
await conn.query(cypher)                    // ✓
const res = await conn.query(cypher);
await res.getAll()                          // ✓ 取数
JSON.stringify(res.getAll())                // ✗ 得到 "{}"，那是个未 await 的 Promise

conn.query(cypher, { id: 1 })               // ✗ progressCallback must be a function
const stmt = await conn.prepare(cypher);    // ✓ 带参数必须走 prepare + execute
await conn.execute(stmt, { id: 1 })
```

参数化写入还顺带解决了 LaTeX 反斜杠被当作转义符的问题。

### 3. 同一个库文件只能打开一个 Database 实例

单写者模型，重复 open 报 `Could not set lock on file`。
统一走 `src/kuzu.mjs` 的 `getDb()` 单例。

### 4. Kuzu 里连续两个 OPTIONAL MATCH 会丢作用域

第二个 OPTIONAL MATCH 引用不到第一个引入的变量，报 `Binder exception: Variable s is not in scope`。
拆成独立查询再在 JS 里合并。

### 5. GLM-5.3 是推理模型，有两个字段

```
delta.reasoning_content   思考过程（不是答案）
delta.content             正式回答
```

混进正文会严重污染输出。本项目把思考过程走独立的 SSE `reasoning` 事件，前端折叠展示。

### 6. 建库用 DROP TABLE，不要删库文件

本环境的 `fs.rmSync` 被安全策略接管为"移入回收站"，在数据目录上会失败。
`resetSchema()` 先 DROP 关系表再 DROP 节点表，既绕开限制又保证脚本幂等。

### 7. 视觉模型的模型名不在 `/models` 返回的清单里

`GET /models` 只返回 11 个**文本**模型（`glm-4.5` ~ `glm-5.3-flashx`），
视觉模型（`glm-4v-plus` / `glm-4.5v` / `glm-4v` / `glm-4v-flash`）一个都不在里面。
别因为"清单里没有"就以为不能用——直接发一次真实图片请求才是可靠的验证方式。
这些视觉模型与文本模型**共用同一个 `GLM_API_KEY`**，不需要另外申请。

### 8. 不要用推理模型做识别

`glm-4.5v` 在识别任务上反而更差：它看到图里的错字会"顺着上下文纠正"，
把 `electonmignttic` 原样抄下来（说明它在按字面读，而没真正理解这是 `electromagnetic` 的误写）。
`glm-4v-flash` 则会在识别时顺手补完推导——**越界**。

识别任务的 temperature 要压到 0.1，模型要选偏"看得准"而不是偏"想得多"的。

### 9. 识别环节必须禁止"自作聪明"

这是设计上最容易踩的坑：如果告诉识别模型"把题目转写成规范的 LaTeX"，
它会顺手把看起来不对的公式"修正"成物理上合理的版本。
结果就是下游完全无法分辨"这是书上印错了"还是"这是模型改过了"。

正确做法是把职责切干净：**识别只负责看，诊断才负责判断**，
识别阶段的提示词里要明确写"照原样转写，不要修正、不要解题"。

### 10. 浏览器缓存旧前端会造成"改了没生效"

本项目前端是单文件 `index.html`，经常随代码一起改。浏览器若缓存了旧页面，
旧 JS 调新后端接口会对不上号（SSE 事件格式变了就"卡住无反应"），这类问题极难排查。

服务端已对 HTML 设置 `Cache-Control: no-cache`（见 `server.mjs` 静态服务段），
但**已经打开着的旧标签页仍是旧代码**——前端有改动后，务必刷新页面（Ctrl+F5 最稳）。
